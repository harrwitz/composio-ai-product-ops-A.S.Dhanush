🤖 Agent Architecture & Human-in-the-Loop Workflow

Built with Python, BeautifulSoup, and the Composio SDK (composio.Composio). The agent combines automated developer documentation retrieval with human-in-the-loop verification loops.

1. Doc Retrieval & Scraping
Directly targets developer documentation URLs, fetching raw HTML pages with SSL unverified contexts and logging HTTP status codes, byte sizes, and latencies to data/fetch_log.jsonl.
2. Composio SDK Live Queries
Loads COMPOSIO_API_KEY securely from .env and queries Composio's API backend (backend.composio.dev) to match apps against its live toolkit catalog (58 Composio matches).
3. Dual-Path Execution
Automated path: URL → fetch → evidence extraction → Composio matching → structured row → confidence/verdict.
Human path: sample audit → inspect real docs → identify false positives / stale URLs / fuzzy toolkit matches → targeted deterministic corrections → regenerate presentation only.

Research & Pipeline Limitations
  • Documentation availability ≠ product capability: A lack of public REST docs does not mean an app lacks internal or partner integration endpoints.
  • HTTP fetch limitations: Static HTTP fetches fail when encountering WAF blocks (HTTP 403), SPA client-rendering, or moved documentation paths.
  • Composio fuzzy matches: Slug-based matching can identify a general parent toolkit (e.g. 'Zoho' or 'LinkedIn') rather than a sub-brand toolkit.
  • Sampled verification: Human ground-truth auditing was conducted on a 20-app stratified sample, not manually across all 100 apps.
  • API breadth heuristic: API breadth is a research classification based on extracted spec pages, not an exhaustive endpoint count.
